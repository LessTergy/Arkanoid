# Как добавить новый бонус

[К индексу](README.md) · [Stage 8](Stages/08-bonus-composite.md)

Новый бонус — один скрипт поведения, один pickup-префаб и запись в существующем профиле дропа. DoubleBall ниже — условное имя; функциональность из названия не предполагается.

## 1. Скрипт поведения

Создать `Assets/Content/Scripts/Runtime/Bonus/DoubleBallEffect.cs` в namespace `Arkanoid.Bonus`. Класс наследует `BonusEffect` и реализует `public override void Apply()`.

Необходимые игровые зависимости получить собственным методом с `[Inject]`. Пример существующего AddLifeEffect получает только LivesModel и вызывает TryAddLife; DoubleScore получает только свой calculator. Получать контейнер из эффекта или расширять общий контекст не нужно.

Параметры, которые действительно должны настраиваться, разместить в `[SerializeField] private` полях компонента. Отдельный ScriptableObject нужен только при реальном переиспользовании данных; обязательных config/definition-классов нет.

Если нужная игровая операция уже существует, вызвать её. Если бонус вводит новую механику, реализовать её у соответствующего владельца и при необходимости зарегистрировать новую зависимость в GameplayLifetimeScope. Сам effect регистрировать не требуется.

До реализации определить повторный подбор и сброс временного состояния. Pickup уничтожается после подбора, поэтому длительная механика, подписки или таймеры должны принадлежать игровому объекту/сервису со своим сроком жизни.

## 2. Pickup-префаб

После компиляции создать Prefab Variant от `Assets/Content/Prefabs/Gameplay/Bonuses/BonusPickup.prefab`. Назвать `DoubleBallPickup.prefab`, сохранить в той же папке.

Открыть variant и добавить DoubleBallEffect на корень с BonusPickup. На корне должен быть ровно один enabled BonusEffect; ссылки Effect в Inspector нет. Шаблон BonusPickup не содержит поведения, поэтому чужой эффект не наследуется.

Настроить внешний вид, имя корня и параметры компонента. Сохранить активный root, слой Pickup, Rigidbody2D Kinematic/Simulated, unlocked Y, enabled trigger BoxCollider2D и назначенные Rigidbody/Collider на том же корне. Не применять специфические изменения variant к общему шаблону.

Скрипт DoubleBallPickup, отдельная фабрика и assets DoubleBallEffect/DoubleBallBonus не нужны. Не добавлять prefab-экземпляр в gameplay-сцену: его создаст общая фабрика.

## 3. Таблица выпадения

В нужном `BonusDropDefinition.asset` добавить Entries:

```text
Pickup Prefab = DoubleBallPickup
Weight        = 1
```

Chance — общий шанс выпадения; Weight — относительный вес среди вариантов при успешном выпадении. Вес должен быть конечным и >0. Профиль должен быть назначен нужным BrickDefinition в поле Bonus Drop.

Для проверки временно использовать Chance=1 и одну запись. Уничтожать непоследний разрушаемый блок; последний бонус не порождает. После проверки вернуть нужную таблицу/шанс.

BonusFactory создаёт prefab через IObjectResolver.Instantiate и внедряет зарегистрированные зависимости во все его компоненты. BonusPickup отвечает за физику и однократность; handler вызывает найденный effect.Apply(). Фабрика и обработчик не дополняются ветками по новому типу.

## 4. Проверка

Проверить собственное действие бонуса, отсутствие посторонних изменений, повторный подбор, паузу, пропуск в DeathZone и выбранные правила сброса. Для новой логики добавить осмысленные тесты; регистрация механики и новые prefab assets могут потребовать проверки в player build.

BonusIntegrationTests содержит пример RecordingBonusEffect: новый компонент получает LivesModel без регистрации своего типа, работает через общий drop/factory/handler и физический подбор. Реальные назначения prefabs проверяет BonusContentTests.

Новый бонус не требует enum, switch в фабрике, изменения общего контекста или класса ScriptableObject для передачи одной ссылки.
