## Правила движения

- В свободном полёте мяч движется по прямой; стены отражают направление, а точка контакта с платформой задаёт новый угол отскока. Скорость удерживается на целевом значении из `BallConfig`.
- `minimum vertical component` ограничивает почти горизонтальные траектории, а `minimum horizontal component` — почти вертикальные. Ограничения действуют после запуска, столкновений и отскока от платформы. `maximum correction threshold` не используется: у него нет однозначной роли в этих правилах.
- `BallConfig` хранится в `Assets/Content/Data/Ball`: начальные `speed = 8` units/s, угол запуска `15–45°` от вертикали вверх симметрично влево и вправо, `minimum vertical component = 0.5` как минимальное `|y|` и `minimum horizontal component = 0.2` как минимальное `|x|` нормализованного направления.
- Мяч начинает в состоянии `Attached`. Допустимые переходы: `Attached → Flying → Lost`; сброс переводит любое состояние в `Attached`.
- В `Attached` мяч следует за платформой с настраиваемым вертикальным смещением без участия в 2D-физике. Нажатие `Launch` задаёт случайное нормализованное направление в диапазоне `BallConfig` и начальную скорость. `BallController` и `BallConfig` регистрируются в `GameplayLifetimeScope` через прямые ссылки.
- В `Flying` каждый physics tick приводит скорость к `BallConfig.Speed`, сохраняя направление после столкновения. При почти нулевой скорости восстанавливается последнее ненулевое направление.
- При контакте мяча с платформой сверху точка контакта по X переводится в диапазон `[-1, 1]` относительно её ширины. Центр направляет мяч почти вертикально вверх с небольшим отклонением в сторону прежнего движения, левый и правый края дают максимальный наклон в соответствующую сторону; `minimum vertical component` ограничивает наклон. Новое направление сразу получает скорость `BallConfig.Speed`.

## Проверочное поле для P2.5

Для проверки скорости в `Gameplay` нужны четыре статические стены на слое `Wall`, а экземпляр мяча должен быть на слое `Ball`. Каждая стена — отдельный `BoxCollider2D` с выключенным `Is Trigger` и материалом `BallPhysics.physicsMaterial2D`; `Rigidbody2D` стенам не нужен. Для текущего `PlayfieldCamera.WorldBounds` (`x = -5.4…5.4`, `y = -8.6…10.6`) и толщины `0.5` использовать мировые координаты:

| Объект | Position (X, Y) | Collider Size (X, Y) |
|---|---:|---:|
| `LeftWall` | `(-5.65, 1)` | `(0.5, 20.2)` |
| `RightWall` | `(5.65, 1)` | `(0.5, 20.2)` |
| `TopWall` | `(0, 10.85)` | `(11.8, 0.5)` |
| `TemporaryBottomWall` | `(0, -8.85)` | `(11.8, 0.5)` |

Внутренние грани совпадают с логическими границами поля. Нижняя отражающая стена использовалась только для повторных отскоков при проверке `P2.5`; в `P2.8` её заменили на trigger `DeathZone`, сохранив остальные три стены. Реакция игры на вход мяча в `DeathZone` относится к `P3.6`.
