# Рефакторинг после этапа 3

[Назад: этап 3](03-playable-slice.md) · [К индексу](../README.md) · [Далее: этап 4](04-vcontainer.md)

**Результат:** первый playable slice сохраняет поведение, а переходы игрового процесса, жизненный цикл объектов и данные для физики имеют понятных владельцев. Этот план выполняется после `P3.11` и до окончательной проверки `Gate 3`.

**Область:** рабочий код в `Assets/Content/Scripts` и необходимые регрессионные тесты в `Assets/Content/Tests`. Настройку сцен, prefab и ссылок Inspector выполняет пользователь, если отдельно не поручит это агенту; результат проверяется в Unity вручную.

## Порядок работы

Задачи выполняются строго сверху вниз. Следующая начинается после проверки результата предыдущей. При каждом изменении сохраняются существующие правила запуска, потери жизни, победы, паузы и перезапуска. Новые игровые возможности в этот план не входят.

- [x] `R3.1` Зафиксировать регрессионную проверку текущего игрового цикла. Использовать существующие EditMode-тесты `GameSession`/`LivesModel` и PlayMode-тест победы; добавить PlayMode-проверку потери первых двух и последней жизни через физический trigger. Проверить в Unity запуск, паузу, победу и restart. **Критерий:** известен исходный результат каждого сценария до рефакторинга.
- [x] `R3.2` Вынести сценарий потери жизни из `DeathZone` в обработчик игрового процесса. `DeathZone` должен сообщать о попадании нужного мяча; обработчик последовательно обновляет `LivesModel`, останавливает и размещает мяч и платформу, переводит `GameSession` в `Ready` либо `GameOver`. При событии `StateChanged(LifeLost)` новое число жизней уже должно быть доступно подписчикам. **Критерий:** первые два попадания возвращают игру в `Ready`, третье приводит к `GameOver`; одно попадание не отнимает две жизни.

- [x] `R3.3` Отделить решение о запуске партии от состояния мяча. Обработчик игрового процесса принимает `Launch`, проверяет допустимый переход `GameSession` и запускает `BallController`; состояния мяча отвечают за движение и физику. Сохранить запуск только из `Ready`. **Критерий:** ввод запускает мяч и сессию ровно один раз, после потери жизни запуск работает снова, при `GameOver` и `LevelComplete` запуск запрещён.

- [x] `R3.4` Уточнить контракт перезапуска. Текущая кнопка перезагружает `Gameplay`, а `GameSession.Restart()` и `LivesModel.Reset()` сбрасывают только отдельные модели. Сохранить перезагрузку сцены как текущий способ полного restart; после проверки вызывающих мест переименовать, ограничить или удалить частичные API, которые можно ошибочно принять за полный перезапуск. Обновить затронутые тесты и описание этапа. **Критерий:** у каждого оставшегося метода сброса однозначное назначение; кнопка восстанавливает блоки, жизни и состояние `Ready`.

- [x] `R3.5` Разделить получение зависимостей и инициализацию в `GameplayHudPresenter`, `GameplayPauseController` и `LevelFinishedHandler`. Конструкторы только принимают зависимости; подписки, первоначальное отображение и другая работа выполняются в явном этапе жизненного цикла, отписки — при его завершении. Проверить регистрацию в `GameplayLifetimeScope` без дублирования подписок. **Критерий:** одно создание gameplay scope даёт одну подписку на каждое событие, выгрузка снимает подписки и восстанавливает паузу. Общую проверку lifetimes и entry points оставить `P4.1–P4.5`.

- [x] `R3.6` Удалить избыточный `BallView`. `BallController` хранит `Rigidbody2D` и отвечает за размещение, запуск и остановку мяча; состояние полёта получает компонент через контроллер для расчёта направления и отскока. Инициализацию `Rigidbody2D` выполнять явно в `Awake()` контроллера. **Критерий:** поведение запуска, отскока, остановки и прикрепления не меняется; промежуточного держателя компонентов нет.

- [x] `R3.7` Устранить расхождение настроенных и фактических размеров. `PaddleConfig.Width` задаёт начальную ширину; `PaddleMovement.SetWidth` применяет её к `SpriteRenderer` в режиме `Sliced` и `BoxCollider2D`, а ограничение движения и отскок используют текущую ширину коллайдера. Положение прикреплённого мяча отсчитывается от касания коллайдеров; неотрицательный `offsetY` задаёт дополнительный зазор. **Критерий:** изменение размера платформы не требует незаметной ручной синхронизации второго значения; ручная проверка крайних отскоков проходит.

- [ ] `R3.8` Убрать пользовательские подписи `Lives`, `Score`, `Pause` и `Resume` из `GameplayHudPresenter`. Хранить оформление текста на стороне UI и передавать из presenter только данные и состояние; оставить `Score` заглушкой до этапа подсчёта очков. Не выносить в настройки осмысленные правила `InitialLives = 3`, `Time.timeScale = 0` и значения по умолчанию в `BallConfig`/`PaddleConfig` только ради устранения литералов. **Критерий:** HUD по-прежнему показывает жизни, счёт-заглушку и состояние кнопки паузы.

- [ ] `R3.9` Привести Inspector к понятным группам: `GameplayLifetimeScope` (input, paddle, ball, level, UI), `InputSystemPlayerInput` (actions, camera), `GameplayHudView` (text, buttons). Добавлять `[Header]` только там, где он разделяет несколько полей. Сохранить сериализацию и существующие ссылки prefab/сцены. **Критерий:** Inspector читается по группам, все обязательные поля назначены; никакие ссылки не потеряны.

- [ ] `R3.10` Проанализировать длинные условия `if` в `Assets/Content/Scripts`. Там, где составное условие или вычисление трудно читать, вынести его в локальную переменную с именем, описывающим смысл проверки. Не вводить переменные для простых условий и сохранить порядок вычисления и побочные эффекты. **Критерий:** найденные сложные проверки читаются по смыслу, поведение и существующие тесты не изменились.
