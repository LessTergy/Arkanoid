# Этап 5. Расширяемый расчёт счёта через Decorator

[Назад: этап 4](04-vcontainer.md) · [К индексу](../README.md) · [Архитектура паттернов](../ARCHITECTURE.md#обязательные-паттерны-и-критерии-их-уместности) · [Далее: этап 6](06-brick-hit-chain.md)

**Результат:** базовый счёт, комбо и удвоение очков скомпонованы через Decorator без связанных между собой условных веток; выбор паттерна обоснован фактическими правилами.

## Задачи

- [ ] `P5.1` Полностью записать правила счёта примерами: base score, combo, double score, combo+double и reset при потере мяча.
- [ ] `P5.2` Определить минимальный контракт расчёта и необходимые входные данные, не закладывая будущие модификаторы, которых ещё нет.
- [ ] `P5.3` Реализовать базовый расчёт и `ComboModel`; покрыть их тестами до добавления double score.
- [ ] `P5.4` Сравнить одну явную формулу, ordered modifier pipeline и Decorator. Зафиксировать, почему при независимых `Combo` и `DoubleScore` декораторы лучше изолируют правила и явно показывают порядок композиции.
- [ ] `P5.5` Реализовать `ComboScoreDecorator` и `DoubleScoreDecorator` поверх общего `IScoreCalculator`; собрать композицию вида `DoubleScore(ComboScore(BaseScore))` в одном composition/factory-коде.
- [ ] `P5.6` Явно зафиксировать порядок применения combo и multiplier и проверить его примерами в тестах.
- [ ] `P5.7` Реализовать `ScoreService`, который принимает результат calculator/pipeline, изменяет total и публикует событие для HUD.
- [ ] `P5.8` Связать уничтожение блока со `ScoreService`, не связывая BlockView напрямую с UI.
- [ ] `P5.9` Показать score и combo в HUD; анимацию оставить на этап polish.
- [ ] `P5.10` Добавить parameterized tests Decorator-композиции: base score, combo, double, combo+double, reset combo, отсутствие отрицательного результата.
- [ ] `P5.11` Кратко записать в README, почему Decorator выбран для этой механики и в каком случае более простой pipeline был бы предпочтительнее.

## Gate 5

- [ ] Правило base score не знает о деталях combo и double score.
- [ ] Каждый decorator реализует тот же контракт, делегирует вложенному calculator и тестируется отдельно и в композиции.
- [ ] Порядок модификации результата виден в одном месте и подтверждён тестами.
- [ ] Добавление нового реального modifier не требует менять логику существующих modifiers.
- [ ] HUD отображает тот же итог, который хранит `ScoreService`.
